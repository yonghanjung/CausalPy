## 2. 아키텍처 이해 (맥락)

- **graph layer** (`graph.py`): ADMG를 `nx.DiGraph` 하나로 표현. latent는 `U` 접두사 노드, bidirected는 `U_A_B -> A`, `U_A_B -> B` canonical 인코딩. treatment `X*`, outcome `Y*`, 기타 `V*`. c-component, ancestor/descendant, edge cut($G_{\bar X}$, $G_{\underline X}$), random ADMG 생성.
- **identification layer**: `identify.py`(ID 알고리즘, c-tree/AC-tree, hedge 비식별), `adjustment.py`(backdoor/adjustment criterion), `mSBD.py`(sequential backdoor SAC), `frontdoor.py`(constructive FD), `tian.py`(Tian/generalized Tian, MC/WMC). 식별 가능성을 판정하고 symbolic estimand 문자열/LaTeX를 만든다.
- **estimation layer**: `est_mSBD.py`(현재 살아있는 추정기: BD/SBD/mSBD에 대한 OM/IPW/DML cross-fitting), `est_general.py`/`est_plugin.py`/`est_Tian.py`(AC-tree c-component/Tian 추정기), `statmodules.py`(XGBoost nuisance, OSQP balancing, ground truth, 성능), `UCA.py`.
- **SCM/data layer**: `SCM.py`(구조방정식·샘플링), `example_SCM.py`(named ground-truth SCM), `examples.py`(graph fixture), `random_generator.py`(random ADMG/SCM 탐색).
- **experiment layer**: `simulation.py` + `load_*.py` (Monte-Carlo 추정기 비교·플롯).

핵심 설계 의존성: 거의 모든 알고리즘이 노드 이름 접두사(`X/Y/U/V`)에 강하게 의존한다. 이름 규칙을 벗어나면 조용히 틀린다 (BUG-L07 참고).

#### BUG-H05: `partition_Y`의 Y-분할 인덱스 오타  **[정정: 실제 BENIGN, §0.1 참조]**
- **파일**: `mSBD.py:33` (함수 `partition_Y`, 라인 30-41)
- **심각도**: ~~High~~ → Low (출력 불변, 환경에서 검증 완료, 1글자 교정만 적용)
- **확신도**: High (직접 통독 + grep + 환경 검증).
- **코드**:
```python
for i, Xi in enumerate(X):
    so_far_Y = list()
    for j in range(i+1):
        so_far_Y += partition[f'Y{i}']   # BUG: f'Y{i}' 가 아니라 f'Y{j}' 여야 한다
    remaining_Y = list(set(Y) - set(so_far_Y))
```
- **원인/실패 시나리오**: `so_far_Y`는 "지금까지 배정된 $Y_0 \cup \cdots \cup Y_i$"여야 하는데, 루프 변수 `j` 대신 고정 `i`로 인덱싱한다. $i \ge 1$부터 `so_far_Y`가 $Y_i$ 하나만 담아 $Y_0..Y_{i-1}$를 누락한다. 결과적으로 이미 배정된 outcome이 이후 분할에 다시 들어가 **분할이 겹친다**. treatment 1개($len(X)=1$)면 $i=0$만 돌아 우연히 맞다. 다중 treatment(sequential, mSBD의 존재 이유)에서 partition이 틀린다. 이 함수는 mSBD/SAC criterion과 estimand 전체의 기반이다.
- **제안 수정**: `partition[f'Y{j}']`로 교정.

#### BUG-H06: sequential IPW/DML 누적 가중치  **[판정 철회: 버그 아님 — 제안 수정은 HARMFUL, §0.1 참조]**
- **파일**: `est_mSBD.py:335-343` (`estimate_SBD`), `est_mSBD.py:538-546` (`estimate_mSBD_y`), `est_mSBD.py:719-722` (`estimate_mSBD_xy`). DML 보정은 `:355-359`, `:558-562`, `:724-727`.
- **심각도**: ~~High~~ → 철회. IPW는 정상(현재 last-stage 코드가 옳음). DML 비작동만 BUG-N01로 남음.
- **확신도**: 환경에서 noise-free 검증 완료 (1차 정적 판정은 틀렸음)
- **코드** (`estimate_mSBD_xy`):
```python
pi_accumulated = np.ones(n_samples)
for i in range(1, m + 1):
    pi_accumulated = pi_preds[(i, x_val_tuple)] # Note: This line preserves the bug from the base function
estimator_outcomes['IPW'] = pi_accumulated * Yvec
```
- **원인/실패 시나리오**: 루프가 가중치를 곱(product)으로 누적해야 하는데 매 반복 **덮어쓴다**. 결과적으로 IPW는 마지막 stage 가중치 $\pi^m$만 쓴다. `np.ones` 초기화와 주석("multiply them sequentially")이 의도가 product임을 보여준다. DML은 `pi_acc_dict[i] = pi_preds[(i,x_val)]`(단일 stage)을 EIF telescoping에 쓰는데, 누적곱 $\pi^1\cdots\pi^i$가 아니라 단일 stage 가중치라 doubly-robust telescoping이 성립하지 않는다. $m \ge 2$ sequential에서 IPW/DML 점추정과 CI가 틀린다. (`estimate_BD`는 단일 stage라 무관, OM 경로는 정상.)
- **제안 수정**: ~~누적곱으로 정정~~ → **적용 금지.** 누적곱은 stage별 정규화를 깨 IPW를 $P>1$로 발산시킨다(§0.1에서 환경 검증). 현재 last-stage 코드가 옳다. 위 "원인/실패 시나리오"의 product 의도 추론은 틀렸다. DML 비작동(N01)만 별도 과제(paper 기반).

## 4. Cross-cutting 테마

1. **전파되지 않은 리팩터 (가장 큰 테마)**: `est_mSBD.py`의 per-realization API가 `estimate_mSBD_xy` 계열로 바뀌고 `est_BD.py`/`graph.unfold_graph_from_data`가 사라졌는데, `est_general.py`/`est_plugin.py`/`est_Tian.py`는 옛 이름을 그대로 호출한다. estimation의 "general/Tian/c-component" 전체와 simulation dispatcher가 죽었다. (BUG-H01~H04)
2. **추정기 이름 schism (`IPW` vs `IW`)**: `est_mSBD`는 `IPW`를 내고 플롯은 `IW`를 기대한다. driver에 `IW`가 새어 들어가 simulation을 크래시(BUG-H07)시키고, 플롯 rename은 CoW에서 사라진다(BUG-M14). 단일 진실원천은 `['OM','IPW','DML']`이며 `IW`는 플롯 라벨에서만.
3. **재현성/시드**: `SCM.generate_samples(seed=None)` 비재현(BUG-M09), `random_generator`의 float seed(BUG-H08)와 self-reseed(BUG-M19)로 random 탐색이 결정적 궤적으로 붕괴.
4. **caller 데이터 in-place 변형**: `est_mSBD`가 `obs_data`에 컬럼을 직접 추가하고(BUG-M05) 전역으로 chained-assignment 경고를 끈다(`est_mSBD.py:27`).
5. **naming 규칙 의존**: `X/Y/U/V` 접두사 가정이 코드 전반에 박혀 있고 내부에서도 불일치(BUG-L07).
6. **테스트 부재**: `test_*` 파일이 assert 없는 print 드라이버라 회귀 보호가 없다(BUG-L10). 위 결함들이 오래 살아남은 구조적 이유.

## 6. 검증 상태 / Caveats

- **직접 확인**: BUG-H01~H03, H05, H06, H08, H09, M01~M07, M17, M18, M19, L01~L11과 H04의 시그니처는 내가 소스를 직접 읽었거나 grep으로 확인했다.
- **sub-analysis 기반(라인 단위 직접 재독은 하지 않음)**: BUG-M09~M16, L12, 3.4의 LT01~LT07. 라인 번호와 근거는 함께 적었으나, 수치 로직의 최종 확정은 해당 함수를 실행/재독해 재확인 권장.
- "환경에서 import 불가"류(예: `pyvis`/`dill`)는 분석 샌드박스 기준이다. 사용자의 기존 venv(`CausalPy/CausalPy/`)에는 설치돼 있을 수 있으므로, **검증된 사실은 "`requirements.txt` 누락"**이다(BUG-M17).
- 본 보고서는 진단만 담는다. 어떤 소스도 수정하지 않았고, CausalPy 자체 `.git`에 commit/push도 하지 않았다.
